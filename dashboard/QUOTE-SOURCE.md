# 行情源怎么选：直连 vs 家里服务

> 这份文档覆盖了早期"走家里服务更好"的结论（原 DEPLOY.md 已删除）。板子放在公司后，那个结论不再成立，理由见下。

## 一句话结论

**板子在公司的场景，让板子直连，不要绕家里。**

配置就是默认值，什么都不用填：

```json
{ "quote_url": "", "quote_pref": 0 }
```

家里服务留着给**人在外面用手机看**——那是它唯一不可替代的用途。

## 为什么（三个数字推翻了我原来的论证）

我最初推荐家里服务，核心理由是"能省掉 TLS 握手"。**这个理由在板子放到公司后就不成立了**：

| | 直连 | 走家里服务 |
|---|---|---|
| 请求数 | 2 次（腾讯明文 1 + 东财 TLS 1） | 1 次 |
| **TLS 握手次数** | **1 次**（东财） | **1 次**（隧道 HTTPS） |
| 单次耗时（MCU 上估算） | 0.2s 明文 + 0.3s 传输 + 1.0s 握手 ≈ **1.5s** | 握手 1.0s + 隧道转发 0.1s ≈ **1.1s** |
| 故障点 | 腾讯、东财 | 腾讯、东财 **+ 家里断电 + 家里断网 + 隧道挂 + Mac 睡眠** |
| 手机能否看 | 不能 | 能 |

关键那一行：板子在公司，家里服务只能经隧道暴露，**隧道本身也是 HTTPS**。所以不管走哪条路，MCU 都要做一次 TLS 握手——省不掉。

耗时差别只有 0.4 秒左右（而且是我估算的，真机可能更接近），但直连少四个故障点。对一块挂在墙上的屏，**稳定比快 0.4 秒重要得多**。

另外东财已换成批量接口，一次请求拿 63 个指数、稳定不空包，所以"服务端帮忙重试"这个好处也基本没用了。

## 什么时候该反过来（`quote_pref: 1`）

只有一种情况：**公司网络把 `push2.eastmoney.com` 挡了**，直连拿不到日经/韩股。

不过这种情况你不用手动切——固件默认 `quote_pref: 0` 已经做了"直连缺格时自动用家里服务补齐"：

```
直连拿到 10 个（缺 N225、KS11）
  → 发现不足 12 个，且配了 quote_url
  → 额外请求一次家里服务，只补缺的那 2 个
```

所以想加保险的话，`quote_url` 可以填上，`quote_pref` 保持 0。代价是**只有缺格时**才多一次请求。

| 分支 | 行为 |
|---|---|
| `quote_url` 空（默认） | 纯直连，2 次请求 |
| `quote_url` 有值 + `pref: 0` | 直连优先；缺格才用服务器补 |
| `quote_url` 有值 + `pref: 1` | 服务器优先；服务挂了自动回退直连 |

## 家里服务真正该干的活

| 用途 | 是否必须 | 说明 |
|---|---|---|
| 人在外面用手机看行情 | **必须** | 直连方案没有这个能力 |
| AI 简报页 | **必须** | 要 POST + API key + 等 2~5 秒，MCU 做不了 |
| 历史曲线 / 多设备共享 | 可选 | 以后想做再说 |

## 唯一的风险点

东财按 IP 限流（密集请求会被整段拒绝）。板子在公司时用的是**公司出口 IP**，按 15 秒 1 次算是 5760 次/天，正常不会触发——之前触发是因为我连续发了几十次。

万一公司有人（或别的程序）也在猛刷东财，可能连带受影响。这时候上面的"缺格补齐"就是兜底。
