# 4.2" 墨水屏面板（400×300，SSD1619A，黑白）

固件两个文件，一起拷到板子根目录：

| 文件 | 作用 |
|---|---|
| `epd42.py` | 屏幕驱动（微雪官方 epd4in2_V2 的 MicroPython 移植，命令序列与 233 字节 LUT 原样保留） |
| `epaper_main.py` | 主程序：行情页 + 天气页、三种切页方式、局部/全刷策略、网页控制台 |

原 `main.py` 是 2.8" TFT 版本，保留不动。

## 一、接线（驱动板 V1.5 排针 9 根，接 8 根）

**实物丝印从上到下：GND / 3V3 / SCK / SDA / RST / DC / CS1 / BUSY / CS2。接线照丝印逐根对，不要按位置背顺序。**

| 驱动板丝印 | 含义 | ESP32 默认（可在 config.json 改） |
|---|---|---|
| GND | 地 | GND |
| 3V3 | 屏与驱动板供电 | 3.3V（**不要接 5V**） |
| SCK | SPI 时钟 | GPIO12 |
| SDA | SPI 数据 MOSI | GPIO11 |
| RST | 复位 | GPIO8 |
| DC | 数据/命令 | GPIO9 |
| CS1 | 片选（板默认端） | GPIO10 |
| BUSY | 忙（高=忙） | GPIO7 |
| CS2 | 双芯片大屏用，默认悬空 NC | **不接** |

翻页按键（可选）：一端接 `btn` 配置的 GPIO（默认 4），另一端接 GND；内部已上拉。

## 二、配置

首次启动会生成 `config.json`，改完重启即可（也可以直接在网页控制台改城市/间隔）。

| 键 | 默认 | 说明 |
|---|---|---|
| `ssid` / `pwd` | 空 | WiFi |
| `city` | `101120801` | 城市**代码**（泰安）。中文名接口已失效，必须用代码 |
| `city_label` | `TAIAN` | 屏上代号：屏幕没有中文字库，只能显示拉丁字符 |
| `page_sec` | 60 | 自动翻页间隔 |
| `quote_sec` | 120 | **盘中**（09:00-15:30）行情刷新间隔。走差分（约 1s，不闪）；**低于 120 会被代码顶回 120** |
| `quote_sec_off` | 600 | **非盘中**（早晚时段）行情刷新间隔。护栏 ≥180，且不得小于 `quote_sec` |
| `weather_sec` | 1800 | 天气刷新间隔 |
| `diff_full_every` | 8 | **每几次刷新做一次全刷**（清残影）。1=每次全刷（最干净最闪，等于关差分），8=默认，上限 500（控制台可调，改完立即生效）。再大也有兜底：每天 07:00 时段边界必全刷一次 |
| `full_every` | 1 | 已废弃的旧键，恒为 1，留着只为兼容旧配置文件 |
| `mode` | `box` | 跌的表示：`box` 加框 / `paren` 括号 / `inv` 反白 / `plain` 无 |
| `active_from` | 7 | 工作时段起始小时（含），时段外不取数不刷屏 |
| `active_to` | 20 | 工作时段结束小时（不含），20 = 晚 8 点后静默 |
| `weekend_off` | `true` | 周六周日全天静默 |
| `btn` | 4 | 翻页按键 GPIO，填 -1 关闭 |
| `quote_url` | 空 | 可选：家里聚合服务地址；留空=直连公网 |

控制台上**所有可编辑字段都是改完立即生效**，不等重启（2026-11-03 审计修复）。实现上分三层，改任一层都不会「改了没反应」：

1. **调用时现读**：间隔类（`quote_sec`/`weather_sec`/`diff_full_every`/`page_sec`）、时段类（`active_*`/`weekend_off`/`wx_*`）、`led_bright`——每次用到都重新读 `cfg`；
2. **保存后强制重画**：只被 `draw()` 读取的显示类字段（`mode`/`city_label`/`tz`），保存时把面板的内容指纹清掉并置 `dirty`，绕过「数据没变就不重绘」的去重，下一轮主循环立即差分上屏（约 1s，不闪）；
3. **保存后强制重抓**：只被取数函数读取的位置类字段（`city`/`lat`/`lon`/`quote_url`），保存时清零对应页的取数计时并立即抓一次当前页——改城市不再傻等 `weather_sec`（默认 30 分钟）。

护栏：值没动的保存不会触发任何重刷（改动前快照比对）。

### 静默时段（省请求、防半夜闪屏）

`is_active()` 判定：非周末 且 `active_from ≤ 当前小时 < active_to`。时段外：

- 不取数、不自动翻页、不自动刷屏（屏保留最后一次画面，墨水屏断电也留影）
- 网页控制台照常可访问，状态行显示"静默至明 07:00"
- 按键翻页仍可用（本地切页）；点"立即刷新"仍会强制抓一次数据
- 静默结束自动：重新对时 → 丢弃隔夜旧数据 → 全刷一次 → 绿闪

主循环空转从 200ms 放慢到 1000ms。

## 三、刷新策略（2026-11-03 差分跑通，结论二次推翻旧版）

两条可靠路径，按场景选：

| 情况 | 动作 | 耗时 | 闪屏 |
|---|---|---|---|
| 开机 | `clean()`：先黑后白各一帧（长波形） | 约 8s | 有 |
| 数字/内容变了（行情页常规更新） | **差分 `display_diff()`** | **约 1.0s（TP=20）** | **无** |
| 换页 / 手动刷新 / 连续差分攒够 `diff_full_every` 次（默认 8） | 全刷 `display()`（短波形） | 2.9s | 整屏闪一下 |
| 内容没变 | 不刷 | — | — |

实测依据（每条都在真机上复现过多次；第 4、7 条是 2026-11-03 差分实验后**改写**的）：

1. **只有 `0x22=0xF7` 能驱动全刷。** 差分走 `0x22=0xCF`（bit4=1 寄存器 LUT + bit3=1 黑白差分模式）；`0xC7` 是空转：BUSY 会跑 840ms 左右，屏幕一个像素都不动。
2. **单独发过 `0x04`（Power ON）之后，后续 `0xF7` 全部失效**（退化成"有波形无高压"，840ms、屏不动）。旧版 `init_part()` 里那句 `0x04` 就是"局刷/快刷一直不生效"的元凶。现在驱动里**任何地方都不发 `0x04/0x01/0x06`**，高压交给 `0xF7` 自己的 ENABLE_ANALOG→DISABLE_ANALOG 序列。
3. **窗口 `0x44/0x45` 在能驱动的模式下被忽略**：一律整屏 300 行扫描。所以"只刷变化的几十行"不存在，5.2s 不会因为窗口变窄而变快；窗口只影响 RAM 写入范围。
4. **差分刷新成立（2026-11-03 实测，推翻旧结论）。** 配方：`0x21=0x00`（让红平面透传当"旧帧"）+ `0x32` 写 **70 字节** LUT（规格书格式）+ `0x24` 新帧 + `0x26` 旧帧 + `0x22=0xCF`。只有 (旧,新) 真正不同的像素被驱动，照片验证图案精确呈现。旧结论"0x26 只是红平面、差分不成立"的错因：`init()` 一直发 `0x21=0x40`（红平面旁路成 0），旧帧从未启用过。
5. **自定义 233 字节波形表能被 `0xC7` 执行**（耗时随帧数线性变化，确实进了波形引擎），但它是**整屏统一驱动、与 RAM 数据无关**：8 帧没反应，129 帧能把整屏连同黑带一起漂白。改 LUT 画不出图案。（差分的 70 字节表是另一套格式，见第 4 条。）
6. **`0x1A=0x1E00`（30°C 档）把全刷从 5.2s 压到 2.9s**，出图正常。这是目前唯一可靠的全刷提速手段，`init(short=True)` 默认就用它；`clean()` 临时切回长波形（`0x07FF`）拉得更干净。
7. **差分 LUT 必须是 70 字节。** SSD1619A 规格书里 `0x32` 只收 70 字节（VS 5组×7 + TP/RP 5组×7）；按 SSD1683 的 233 字节写，多出的字节会被当成后续命令吞掉，波形静默空转 195ms——这是 2026-11-03 之前所有差分实验失败的根因。TP0（第 35 字节）控制波形时长，总耗时约 `193 + 40.3×TP` 毫秒：TP=40→1.8s，20→1.0s，10→0.6s。

### 差分的电压极性与槽位（2026-11-03 实测）

- 槽位按 (旧位, 新位) 选波形：槽0=黑→黑、槽1=黑→白、槽2=白→黑、槽3=白→白。
- VS 高 2 位：`00`=VSS（保持）、`01`=VSH1（**驱动成黑**）、`10`=VSL（**驱动成白**）。
- 差分 LUT 用 `VS=(0,2,1,0,0)`：变化像素单次驱动到位，不变像素保持。
- 刷完必须把 `0x21` 恢复成 `0x40`，否则后续 `0xF7` 全刷会冒红（`display_diff()` 内部已处理）。

### 刷完必须进深睡（2026-11-02 补）

`show()` 现在的完整序列是：`epd_init()` → `epd.display(BUF)` 或 `epd.display_diff(BUF, _prev)` → `epd.sleep()`。

- `epd.sleep()` 发 `0x10=0x01`，把面板推进深睡、撤掉高压。厂家 FAQ 的红线：「待机过程中（即刷新操作后）建议将屏幕设为睡眠模式或断电，**否则屏幕长时间处于高电压状态下可能烧坏屏幕**」。旧版代码从头到尾没调过它，屏刷完一直挂着高压。
- 深睡后必须靠硬件 `RST` 唤醒，所以每次刷新前都要重走 `epd_init()`（内部先 `reset()`），代价约 230ms，可忽略。

### 必须等 BUSY 先拉高（2026-11-03 修）

`0x20` 之后 BUSY 不是立刻拉高的，真机有 0~几十毫秒延迟；**刷新被中断过的屏延迟更明显**。旧 `TurnOnDisplay()` 直接进 `ReadBusy()`，如果那一刻 BUSY 还是低，就会立刻返回「刷完了」——实测出现过 `display()` 25ms 就返回（正常 3.1s），随后 `sleep()` 在波形还在跑的时候发下去，屏被留在半死状态（后续 `0x44` 卡 15s、再刷不出图，只能断电重启恢复）。

现在 `TurnOnDisplay()` 先 `wait_assert()`（最多等 200ms 看 BUSY 拉高），再 `ReadBusy()` 等回落。代价约 1ms，换来的是「刷完才睡」这个前提真的成立。

### 全刷的代价与寿命账

**全刷本身不比局刷更"伤屏"**：厂家按 update 命令计数，不按像素面积，同一次画面变化全刷和局刷都记 1 次。真正决定寿命的是**刷新频率**（厂家：理想情况 100 万次）：

| 间隔 | 每天 | 每年 | 100 万次用完 | 按 50% 保守估 |
|---|---|---|---|---|
| 60s（更早的配置） | 1440 | 52.6 万 | ~1.9 年 | ~1 年 |
| **120s（当前）** | 720 | 26.3 万 | ~3.8 年 | ~1.9 年 |
| 180s（厂家建议下限） | 480 | 17.5 万 | ~5.7 年 | ~2.9 年 |
| 300s | 288 | 10.5 万 | ~9.5 年 | ~4.8 年 |
| 600s | 144 | 5.3 万 | ~19 年 | ~9.5 年 |

> 2026-11-02：按用户要求改成 **2 分钟一刷**，代价是理论寿命从 5.7 年降到 3.8 年（含 50% 保守打则 1.9 年）。代码护栏相应从 `>=180` 放到 `>=120`；想回到厂家建议值只需把 `quote_sec` 改回 180。

### 分时段间隔（2026-11-03，用户反馈"太晃眼"后改）

差分上线后，闪屏只剩"换页/定期清理"的全刷；取数间隔仍然按 A 股时段分两档：

| 时段 | 参数 | 值 | 次数 |
|---|---|---|---|
| 工作日 09:00-15:30（含 30 分钟缓冲） | `quote_sec` | 120s | 195 次 |
| 工作日 07:00-09:00 + 15:30-20:00 | `quote_sec_off` | 600s | 39 次 |
| 其余（夜间 / 周末） | — | 不取数不刷 | 0 |

合计约 **234 次/天**，比原来的 390 次/天（7-20 全天 120s）少 40%；其中绝大部分走差分（不闪），全刷只剩开机、换页和每 `diff_full_every` 次（默认 8）差分一次的清理（约 30 次/天）。100 万次理论寿命约 11.7 年（50% 保守估约 5.9 年）。

实现要点：`in_session()` 判时段，`QuotePage.due()` 每次调用都重算 `ttl`，跨过 09:00 / 15:30 立即切档，不需要重启。护栏：`quote_sec >= 120`、`quote_sec_off >= 180` 且不得小于 `quote_sec`。

其余影响，按实际感受排序：

1. **体验**：常规数字更新不再闪（差分只驱动变化像素）；闪屏只剩换页和每 `diff_full_every` 次一次的清理全刷；
2. **残影**：差分驱动力比全刷弱，且 TP 越小越弱 → 对策是连续差分攒够 `diff_full_every`（默认 8）次强制全刷一次；即使把它设得很大，每天 07:00 时段边界（`active` 切换）也会全刷一次兜底，换页/手动刷新同样是全刷；
3. **烧屏**：厂家要求"至少 24 小时更新一次"，我们远超；
4. **功耗**：差分比全刷省，日均可忽略。

### 与网上教程/卖家说法的出入

卖家评论里"主控有两个缓冲区，可以发旧画面和新画面，设定 LUT 让变化部分单次刷新"——**2026-11-03 实测证明这条对 SSD1619A 成立**，但有两个坑：

1. LUT 必须按 SSD1619A 规格书写 **70 字节**；照 SSD1683/微雪教程写 233 字节会被静默吞掉，波形空转 195ms，屏一动不动（这就是最初判定"不成立"的原因）；
2. 必须发 `0x21=0x00` 让红平面透传当旧帧；`init()` 默认的 `0x21=0x40` 会把它旁路成 0，旧帧等于全 0，差分同样不生效。

评论区另一个说法"调内部温度模式（0x18 参数 0x80）"未采用——我们用 `0x1A` 温度寄存器选 30°C 短波形，路径不同、目的相同（压驱动时长）。

## 四、切页三种方式

1. **自动**：每 `page_sec` 秒翻一页；
2. **按键**：按一下立刻翻页（带消抖）；
3. **网页**：浏览器打开板子 IP，点「行情页 / 天气页 / 下一页 / 立即刷新」。

## 五、无线运维（WebREPL，拔线可用）

固件联网后自动起 WebREPL（8266 端口，密码见 `webrepl_cfg.py`）。

```
python3 tools/webrepl.py --put firmware/epaper_main.py main.py   # WiFi 传文件（31KB 约 1.7s，自动 SHA1 回读校验）
python3 tools/webrepl.py "print(os.listdir())"                    # 跑代码（仅 REPL 空闲时可用）
```

注意：`main.py` 的主循环跑着时，REPL 交互（跑代码）不响应——REPL 会话和用户程序互斥，这是 MicroPython 设计。传文件走协议层不受影响，是拔线运维的主力；跑代码/查状态插线用 `sh.py`，或用网页控制台。

烧录固件（bin）永远需要 USB 线，WiFi 没有引导通道。

## 六、行情页顶栏指标（涨跌停家数 + 两市成交额）

顶栏右侧一行，形如 `58/11 10030`，只用数字、不标单位：

| 段 | 含义 |
|---|---|
| `58`（斜杠左） | 今日**涨停**家数 58（同花顺涨停池，含 ST 与北交所） |
| `11`（斜杠右） | 今日**跌停**家数 11（同花顺跌停池） |
| `10030`（空格后） | **两市当日成交额累计 10030 亿元**（实时，不是预测） |

两格取不到数据时显示 `--/--`；成交额取不到时只显示 `58/11`。

> 2026-11-02 修正：这一栏最初显示的是**外推全天预测值**（11 点时约 23500 亿），比当下实际值大 2.4 倍，被误认为数据错误。现在改为显示**实时累计**。外推函数 `est_amount()` 仍保留在代码里，`QuotePage.stats()` 末尾有注释掉的一行，需要看预测时对调即可。

**数据源**：`data.10jqka.com.cn/dataapi/limit_up/limit_up_pool` 与 `lower_limit_pool`，只读 `data.page.total`，`limit=1` 把响应压到约 300 字节。板端实测单次约 0.8s（HTTPS），两次共约 1.6s。东财的 `getTopicDTPool` 在本网络返回 `rc:206` 空数据，别用。

**只在交易时段取**（9:30–11:30 / 13:00–15:00），收盘后 `market()` 直接返回 `None`，顶栏保留最后一次的数字，不白花两次 TLS。

**预测怎么算的**：两市成交额取腾讯 `sh000001` 与 `sz399001` 的第 38 个字段（万元）相加，再按日内成交额 **U 型分布**外推——把一天切成 16 个 15 分钟档，查「已走完的档占全天的多少」，`预测 = 累计 / 进度`。权重表 `AMT_W` 是经验值（开盘半小时最猛、午间最淡、尾盘拉起），运行时不要求数组和为 100，代码会归一化。

代价与误差：这不是线性外推，早盘猛则预测高、午后跳水则预测偏低；权重是通用经验，不随当日成交结构自适应。定位是「量级参考」，不是精确数字——午后 14:30 以后误差已小于 5%。

**为什么是成交额而不是成交量**：成交量（手/股）对指数没意义，两市「成交额」才是市场热度口径。

## 七、排错

| 现象 | 先看 |
|---|---|
| 全白无反应 | 3V3 接对没、FPC 锁扣压紧没、BUSY 是否接成别的脚 |
| 花屏/错位 | 确认屏是 400×300 且驱动 IC 为 SSD1619A（例程按型号选） |
| 一直显示 `--` | WiFi 没连上；串口看 `connect()` 结果 |
| 残影越来越重 | 冷启动会跑 `clean()`；也可以把 `quote_sec` 调大，减少全刷次数 |
| 温度/天气空 | `city` 必须是城市代码，不能写中文名 |
